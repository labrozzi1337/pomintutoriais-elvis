PROMPT 05A — ABRIR O RECORDLY DESKTOP A PARTIR DO PORTAL WEB

Você é um desenvolvedor sênior responsável por IMPLEMENTAR, no repositório Vite+React/Next.js já existente, um botão confiável 'Gravar tela' que abra o Recordly instalado no computador Windows do usuário. Continue o sistema implementado pelos prompts anteriores. Faça alterações reais com testes; mantenha nomes de domínio e comentários em pt-BR e não crie funções, triggers ou RPCs no banco.

1. AUDITORIA: antes de codar, examine a estrutura local do sistema, o Recordly instalado quando acessível e o código da versão estável em https://github.com/webadderallorg/Recordly. Verifique se existe protocolo nativo de abertura de gravação realmente suportado na versão INSTALADA. Não invente 'recordly://gravar'. Documente evidências.
2. ARQUITETURA: Docker executa Vite/Next, worker e FFmpeg NO SERVIDOR. O Recordly permanece aplicativo nativo NO WINDOWS DO USUÁRIO. Não tente abrir um .exe remotamente pelo container, nem embutir a captura desktop num iframe.
3. IMPLEMENTE um pequeno Launcher para Windows, distribuído separadamente, com protocolo próprio (exemplo: estudiotutoriais://abrir) registrado no Windows no contexto de usuário; no navegador, a ação deve acontecer após um clique explícito e respeitar confirmação de abertura de programa externo. O Launcher somente executa operações fixas e permitidas: localizar instalação confiável do Recordly e iniciar seu executável. NÃO aceite comandos, argumentos arbitrários, paths executáveis, código ou scripts vindos da web. Evite elevação de privilégio e shell injection.
4. DETECÇÃO DE ESTADO: NUNCA afirme que Recordly está desinstalado só porque o navegador não confirmou a chamada de protocolo. Distinga: Launcher ausente/não respondeu; Launcher respondeu mas Recordly não foi encontrado; aplicativo aberto com confirmação; usuário cancelou; sistema não suportado. Use desafio temporário por sessão emitido pelo servidor e confirmação autenticada do Launcher/servidor, com validade curta e token de uso único. Não inclua segredo de API, credenciais do usuário ou dados sensíveis na URL. Use mecanismo de pareamento instalável, documente riscos de associação indevida e proteção contra CSRF e replay.
5. UI: botão 'Gravar tela' (ação única); enquanto detecta, mostra status real. Quando Launcher não está instalado, modal 'Instalar integração com Windows' com link para instalar o Launcher; quando Launcher identifica Recordly ausente, modal 'Instalar Recordly' com link para https://github.com/webadderallorg/Recordly/releases e instruções curtas. Não invente URL direta de asset; determine versão e plataforma pela lista oficial ou use a página de releases. Inclua 'Já instalei — tentar novamente'. Não faça download/instalação silenciosa.
6. EXPORTAÇÃO: não diga que abrir Recordly garante upload automático. Após exportar MP4, o MVP deve permitir importação/arrastar e soltar ao portal. Se extensão nativa para enviar MP4 for comprovadamente viável, proponha fase independente com consentimento de upload; não a improvise agora.
7. LICENCIAMENTO: o Recordly é AGPLv3. Não copie, modifique ou distribua código Recordly dentro do nosso app proprietário sem revisão específica da licença. Prefira launcher autônomo que inicie o Recordly sem incorporar seu código. Preserve marcas e links oficiais.
8. TESTES E DISTRIBUIÇÃO: construa pacote de instalação do Launcher para Windows, preferencialmente assinado para distribuição externa; se não for possível assinar, documente o aviso do Windows e não o ignore. Valide Windows com Launcher/Recordly instalados, só Launcher, sem Launcher, usuário cancelando abertura e reinstalação. Gere instruções de instalador e remoção. Teste callback com token expirado, reutilizado e de outra sessão. Garanta que a aplicação ainda permita importação manual do MP4 se Launcher falhar.
9. ENTREGÁVEIS: código fonte do Launcher em pasta independente (ou projeto próprio), pacote instalável quando ambiente permitir, integração Vite/Next com API real, documentação leiga de instalação e limitações, testes executados e lista objetiva de pendências. Sem mocks fora de testes. Não proclame funcionando na máquina de outro usuário sem teste de aceitação real.
